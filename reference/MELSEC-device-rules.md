# デバイス容量の計算と判定

機種別の容量・初期点数・設定単位・対応オプションは [JSON定義](../src/definitions/) で管理する。この資料では、定義を使った計算方法と判定範囲を説明する。

## 容量計算

1K = 1,024、1ワード = 16ビット（2バイト）として計算する。

```text
デバイス使用ワード数 = 点数 × (wordCostPerPoint + bitCostPerPoint / 16)
エリア使用ワード数 = overheadWords + 同じエリアのデバイス使用ワード数の合計
使用率 = エリア使用ワード数 / (設定容量Kワード × 1,024) × 100
```

機種の `deviceOverrides` を共通ルールへ適用してから計算する。非表示のデバイスは除外し、固定デバイスは使用容量に含める。

画面の合計欄では `file`・`fileStorage`・`local` を除外する。ワード／ビット内訳では固定デバイスを除外するが、`overheadWords` はワード内訳に含める。

容量・合計値は小数第3位まで、使用率は小数第1位まで表示する。判定には表示前の値を使う。

## 判定

| 条件 | エリアの表示 |
|---|---|
| 使用率90%未満 | 範囲内 |
| 使用率90%以上、100%以下 | 残り10%以下 |
| 使用率100%超 | オーバー |

設定容量が0の場合、使用量も0なら使用率0%、使用量があれば容量超過とする。

点数の入力不正・設定単位違反・最大点数超過、エリア容量の範囲外、共有メモリの割付超過がある場合も、総合判定は「容量超過 / 要確認」となる。

## メモリ構成とオプション

- 選択肢は機種の `allowedMemoryOptionIds` に限定する。
- `expandWithMemory` のエリア上限には `sharedMemoryAddedKWords` を加算する。
- `capacityFromMemoryOption` のエリアは、`fileCapacityOverrideKPoints` があれば容量を置き換え、なければ `fileCapacityAddedKPoints` を加算する。
- `absoluteMaxKWords` が指定されていれば、増設後もその上限を適用する。デバイスの `maxPoints` は別に判定する。
- 共有メモリは、各エリアの設定容量の合計を検査する。`local` は残容量から自動計算する。
- `memoryBlocks` を持つ機種はブロックごとに設定容量の合計を検査する。ラベル配置を切り替えた場合は、移動先ブロックにラベル・ラッチラベル容量を計上する。
- SRAMカードの管理領域や他ファイルの占有分は自動控除しない。
- SDカードは容量の加算元・選択肢に含めない。

## 入力と割当

- 点数は0以上の整数、または整数点数に換算できるK表記を受け付ける。全角数字にも対応する。
- 入力中は設定単位へ自動補正しない。補正ボタンで切り上げるが、固定デバイスと補正後に最大点数を超える値は変更しない。
- 全領域割当はZR、ZRがなければRを対象とする。同じエリアの変更可能な他デバイスを0点にし、システム使用分と固定デバイス分を除いた容量を、設定単位と最大点数の範囲内で割り当てる。エリアの設定容量自体は変更しない。
- 1列貼り付けは表示順、2列貼り付けは記号またはデバイス名で対応する。途中の空行と固定デバイスは行位置を保ち、値を変更しない。
- 使用範囲は0から点数−1までを定義された進数で表示する。0点は「なし」とする。

## 特記事項

- FX5UJのP/I仕様は共通FX5プロファイルで扱っており、機種固有の点数と使用可能な番号の数え方の整理が未完了。

### 判定の対象外

- プロジェクト内の実際のラベル使用量。ラベルエリアの使用量0は、ラベル未使用を意味しない。
- FX5のラッチ範囲・保持容量判定。
- GX Works3の自動削減。
- SDカード上の拡張ファイルレジスタ。
- 実機への書込みとGX Worksのパラメータチェック。

画面での計算処理は [site.js](../src/site/site.js) にある。生成・テストの手順は [README](../README.md#生成と起動) を参照する。
