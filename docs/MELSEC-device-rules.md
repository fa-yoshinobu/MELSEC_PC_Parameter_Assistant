# MELSEC 機種別デバイス設定・容量計算 調査結果

最終更新: 2026-07-17

## 1. 目的と結論

`Manual` 配下のユーザーズマニュアルと `image.xlsx` の入力例を基に、PLC型式ごとのデバイス点数、設定単位、デバイスメモリ容量、増設SRAMの扱いを整理した。

アプリの判定方針は次のとおり。

- PLCシリーズを先に選ぶと型式候補を絞り込み、PLC型式を選ぶと、その機種のJSONで許可されたメモリオプション、GX Works2/3形式のデバイス入力欄、機種仕様の備考を表示する。PDFの改ページは再現せず、ブラウザー上の1つの連続フォームとする。
- 入力点数をワードへ換算し、領域ごとに使用率を表示する。
- 使用率90%未満を「範囲内」、90～100%を「残り10%未満」、100%超を「オーバー」とする。
- 点数が機種別の設定単位または最大点数に合わない場合も「要確認」とする。
- 機種別の初期点数を入れた状態からWebフォーム上で設定し、完成した型式・容量判定・デバイス点数・機種仕様をExcel貼り付け用TSVとしてコピーする。
- Excelからの1列/2列一括入力は、既存資料を再利用する場合だけの補助機能として折りたたんで表示する。
- 設定中の各デバイスについて、現在の点数と実際に使用できる先頭～末尾番号を入力表および機種仕様・備考に表示する。備考とExcel出力ではKに省略せず実数を使う。
- ZR（ZRがない機種はR）には、ボタン操作で同一領域の割当可能容量をまとめて割り当てられるようにする。
- SDメモリーカードはアクセス速度の観点からデバイスデータ置き場に使用しない。バックアップ用途だけとし、容量計算および選択フォームから除外する。

価格と生産終了状態はWebページからのコピー情報だったため、定義と画面には含めていない。

## 2. 容量換算ルール

### 2.1 GX Works2 / GX Developer系

内部ユーザデバイス容量は、デバイス点数を次の式でワードへ換算する。

| デバイス | 1点あたりの容量 |
|---|---:|
| X, Y, M, L, B, F, SB, V, S | 1ビット = 1/16ワード |
| T, ST, C | 現在値1ワード + 接点/コイル2ビット = 1.125ワード |
| D, W, SW, Z | 1ワード |
| ZR、拡張D、拡張W | 1ワード。ファイル用領域側へ計上 |

計算式は次のとおり。

```text
使用ワード数 =
  (X + Y + M + L + B + F + SB + V + S) / 16
  + (T + ST + C) × (1 + 2 / 16)
  + D + W + SW + Z
```

`image.xlsx` のGX Works2例（Q04UDVCPU相当）では40,148ワード、すなわち39.207Kワードとなり、Excel表示の39.2Kワードと一致した。

### 2.2 GX Works3系（iQ-R / iQ-L / MX-F / MX-R）

| デバイス | 1点あたりの容量 |
|---|---:|
| X, Y, M, B, SB, F, V, S, L | 1/16ワード |
| T, ST | 1ワード + 1ビット = 1.0625ワード |
| LT, LST | 2ワード + 1ビット = 2.0625ワード |
| C | 1ワード + 2ビット = 1.125ワード |
| LC | 2ワード + 2ビット = 2.125ワード |
| D, W, SW, ZR | 1ワード |

デバイスエリアにはシステム使用分2Kワードを加算する。`image.xlsx` のGX Works3例では、デバイス入力分36.375Kワードとシステム使用分2Kワードの合計38.375Kワードとなり、Excel表示の38.4Kワードと一致した。

### 2.3 FX5系

FX5は高速エリアと標準エリアを別々に判定する。点数換算は、ビットデバイスが1/16ワード、通常タイマが1ワード＋1ビット、カウンタが1ワード＋2ビット、ロングカウンタが2ワード＋2ビット、ワードデバイスが1ワードである。

FX5U/FX5UCの設定単位は、主なビットデバイスが64点、T/ST/C/LCが16点、D/R/W/SWが4点。FX5UJはデバイス/ラベルメモリエリア設定を変更できず、機種定義の固定点数を使用する。

## 3. 機種別の容量

容量はKワード。iQ-R、iQ-L、MX-F、MX-Rではデバイス、ラベル、ラッチラベル、ローカル、ファイル格納が同じ共有メモリから割り付けられるため、個別上限だけでなく合計も判定する。

### 3.2 MELSEC iQ-R / iQ-L

| 機種グループ | 共有メモリ初期容量 | 初期割付（デバイス / ラベル / ラッチ / ファイル） | 拡張SRAM |
|---|---:|---|---|
| R00/R01/R02 | 126K | 30 / 30 / 2 / 64K | なし |
| R04 / L04H | 200K | 40 / 30 / 2 / 128K | R04のみ通常SRAM対応 |
| R08 / L08H | 594K | 40 / 40 / 2 / 512K | R08のみ通常SRAM対応 |
| R16 / L16H | 860K | 40 / 50 / 2 / 768K | R16のみ通常SRAM対応 |
| R32 | 1,158K | 40 / 90 / 4 / 1,024K | 通常SRAM対応 |
| R120 | 1,690K | 40 / 110 / 4 / 1,536K | 通常SRAM対応 |
| R08P / R16P / R32P / R120P | 対応するR CPUと同じ | 対応するR CPUと同じ | ECC品2MB/8MBのみ |

通常のiQ-R拡張SRAMは1MBあたり512Kワードを共有メモリへ加算する。プロセスCPU用ECC品もバイト数からの換算は同じで、2MBが1,024Kワード、8MBが4,096Kワードである。`NZ1BLC` は容量増設品ではなく停電保持用として扱う。

iQ-Rの主な設定単位は、M/B/F/SB/V/Lが64点、Sが1,024点、T/ST/C/LCが32点、LT/LSTが1点、D/W/SWが4点。X/Yは固定領域である。R00/R01/R02は初期点数と上限が上位機種と異なるため、専用JSONで上書きしている。

### 3.3 MELSEC iQ-F / MELSEC MX

| 機種 | 容量・初期割付 | 備考 |
|---|---|---|
| FX5U / FX5UC | 高速12K、標準35K（標準は最大63K） | 高速/標準とラベルメモリの合計制約あり |
| FX5UJ | 高速12K、標準35K | メモリエリア設定変更不可 |
| MX-F | 共有4,096K。デバイス192K、ラベル1,854K、ラッチ2K、ファイル2,048K | ローカル/未割付は残容量として自動計算 |
| MXR300-16/-32/-64 | 共有65,536K。デバイス192K、ラベル1,852K、ラッチ4K、ローカル57,344K、ファイル6,144K | デバイス/ラベルメモリ128Mバイト |
| MXR500-128/-256 | 共有131,072K。デバイス192K、ラベル1,852K、ラッチ4K、ローカル120,832K、ファイル8,192K | デバイス/ラベルメモリ256Mバイト |

MX-Fは最新版SH-082633-Eで再確認した。プログラムメモリ30Mバイト、実行プログラムを置くプログラムキャッシュ12Mバイト、デバイス/ラベルメモリ8,192Kバイトである。MX-Rは追加されたSH-082640-DからMXR300系とMXR500系を個別定義した。プログラムメモリは100/150Mバイト、プログラムキャッシュは40/80Mバイトである。

### 3.4 プログラム容量・メモリドライブ・補助デバイス

各機種JSONには `programCapacityKSteps` または `programCapacityText`、`memoryDrives`、`systemDeviceProfileId` を持たせた。型式を選ぶと、計算表の下の備考欄へ次を表示する。

- プログラム容量またはプログラムメモリ/キャッシュ容量
- プログラムメモリ（ドライブ0）、SDメモリカード（ドライブ2）、標準RAMまたはデバイス/ラベルメモリ（ドライブ3）、標準ROMまたはデータメモリ（ドライブ4）など
- P、I、SM、SD、FX、FY、FDの点数。複数形名を1つの定義にまとめた機種で値が異なる場合は形名別の文字列

QnUDVの確定値は次のとおり。

| 機種 | プログラム | ドライブ0 | ドライブ3（標準RAM） | ドライブ4（標準ROM） | P / I / SM / SD / FX / FY / FD |
|---|---:|---:|---:|---:|---|
| Q03UDV | 30Kステップ | 120KB | 192KB | 1025.5KB | 4096 / 256 / 2048 / 2048 / 16 / 16 / 5×4ワード |
| Q04UDV/UDPV | 40K | 160KB | 256KB | 1025.5KB | 同上 |
| Q06UDV/UDPV | 60K | 240KB | 768KB | 1025.5KB | 同上 |
| Q13UDV/UDPV | 130K | 520KB | 1024KB | 2051KB | 同上 |
| Q26UDV/UDPV | 260K | 1040KB | 1280KB | 4102KB | 同上 |

MX系のシステムデバイスは版差を反映した。MX-F（SH-082633-E）はP 8,192点（最大16,384）、I 256点、SM/SD各10,000点、FX/FY各16点、FD 5点×4ワード。MXR300はP 8,192点（最大16,384）、MXR500はP 16,384点（最大32,768）で、両者ともI 1,024点、SM/SD各4,496点、FX/FY各16点、FD 5点×4ワードである。

FX5の割込みポインタは連続範囲ではなく、I0～I15、I16～I23、I28～I31、I50～I177の計156番号を用途別に使用する。SMはSM0～SM9999の10,000点、SDはSD0～SD11999の12,000点。Pはプログラム構成に依存するため固定点数として断定せず、画面ではその旨を表示する。

SDメモリカードは各機種のメモリ構成を比較できるよう備考欄には表示するが、ユーザー指定どおり選択項目およびデバイス容量の加算元にはしない。iQ-Lは提供された応用編（中国語版）のエリア表に加え、追加された `SH-082160CHN-E` 入門編の性能仕様表（印刷ページ20）を照合した。L04H/L08H/L16Hのプログラム容量は40K/80K/160Kステップ、プログラムメモリは160/320/640Kバイト、データメモリは2/5/10Mバイトである。

## 4. メモリオプション

価格および生産終了状態は保持しない。製品名、容量、容量への効果、選択可能機種だけを管理する。

| 分類 | 製品 | 容量効果 |
|---|---|---:|
| Q SRAMカード | Q2MEM-1MBSN | ファイル領域512K点 |
| Q SRAMカード | Q2MEM-2MBSN | ファイル領域1,024K点 |
| Q SRAMカード | Q3MEM-4MBS | ファイル領域2,048K点 |
| Q SRAMカード | Q3MEM-8MBS | 物理換算4,096K点、CPU上限4,086K点を適用 |
| Q 高速タイプ用拡張SRAM | Q4MCA-1/2/4/8MBS | 内蔵容量へ512/1,024/2,048/4,096K点を加算 |
| iQ-R拡張SRAM | NZ2MC-1/2/4/8/16MBS | 共有メモリへ512/1,024/2,048/4,096/8,192Kワードを加算 |
| iQ-RプロセスCPU用ECC | NZ2MC-2MBSE / NZ2MC-8MBSE | 共有メモリへ1,024 / 4,096Kワードを加算 |
| 保持用 | NZ1BLC | 容量は増えない |

`Q2MEM-1MBSN` は `Q2MEM-1MBS` の後継、`Q2MEM-2MBSN` は `Q2MEM-2MBS` の後継として `supersedesProductName` に明示した。旧品も既設設備の計算用に別IDで残している。

PLCごとの選択可否は各 `Definitions/Models/*.json` の `allowedMemoryOptionIds` に持たせる。例えば通常R CPUでは通常SRAM、プロセスCPUではECC品だけが候補になる。共通オプション定義に製品が存在しても、機種JSONで許可されていなければ画面表示も計算もできない。

## 5. SDメモリーカードの扱い

SDメモリーカードはデバイスアクセス用メモリとして扱わない。

- PLC型式JSONの `allowedStorageOptionIds` はすべて `none` のみ。
- 画面にSDカード選択欄を設けない。
- 容量計算へ加算しない。
- `memory-options.json` にはバックアップ用品の参考定義として残すが、PLC機種から選択可能にしない。
- 定義検証で、PLC機種JSONが `none` 以外のストレージを許可していた場合はアプリ起動をエラーにする。

## 6. JSON定義構造

### 6.1 機種定義

```json
{
  "id": "iqr-r04",
  "displayName": "R04CPU / R04ENCPU",
  "ruleSetId": "gxworks3",
  "areas": [
    {
      "id": "device",
      "defaultKWords": 40,
      "minKWords": 2,
      "maxKWords": 200,
      "configurable": true,
      "expandWithMemory": true,
      "overheadWords": 2048
    }
  ],
  "allowedMemoryOptionIds": [
    "none",
    "iqr-sram-1mb",
    "iqr-sram-2mb",
    "iqr-sram-4mb",
    "iqr-sram-8mb",
    "iqr-sram-16mb",
    "iqr-batteryless"
  ],
  "allowedStorageOptionIds": ["none"],
  "programCapacityKSteps": 40,
  "memoryDrives": [
    { "drive": "0", "displayName": "プログラムメモリ", "capacityKBytes": 160 },
    { "drive": "2", "displayName": "SDメモリカード", "capacityText": "装着カード容量", "note": "バックアップ用。容量計算には不使用" }
  ],
  "systemDeviceProfileId": "iqr-standard",
  "deviceOverrides": {
    "M": { "defaultPoints": 12288, "settingUnit": 64 }
  }
}
```

`deviceOverrides` では機種固有の初期点数、上限、設定単位、固定/非表示、計上先エリアを上書きできる。共通式は `Definitions/RuleSets/*.json` に置き、同じ計算方式を機種ごとに複製しない。

P/I/SM/SD/FX/FY/FDの共通値は `Definitions/SystemDeviceProfiles/*.json` に置き、機種JSONからIDで参照する。QnUDVのように個別値を機種JSONへ直接持たせることもできる。これによりマニュアル改訂時の修正箇所を限定できる。

### 6.2 オプション定義

```json
{
  "id": "q-sram-card-1mb",
  "productName": "Q2MEM-1MBSN",
  "supersedesProductName": "Q2MEM-1MBS",
  "sizeMBytes": 1,
  "fileCapacityOverrideKPoints": 512
}
```

- `sharedMemoryAddedKWords`: iQ-R共有メモリへ加算する容量。
- `fileCapacityAddedKPoints`: 内蔵ファイル領域へ加算する容量。
- `fileCapacityOverrideKPoints`: 選択先をSRAMカード容量へ置き換える場合の容量。
- `absoluteMaxKWords`: 内蔵容量と増設容量を合算しても超えられないCPU側の上限。
- `kind: retention`: 停電保持用品。容量効果はゼロ。

## 7. 入力と判定上の注意

- `K` 入力は1K = 1,024点として扱う。例: `8K` は8,192点。
- 通常は機種選択時に入る初期点数から表を直接編集する。初期値へ戻すボタンでいつでも機種定義値へ戻せる。
- 設定単位の補正は入力中には行わない。「設定単位に切り上げ補正」ボタンを押した時だけ、要求点数を下回らない次の単位へ切り上げる（例: 32点単位で100点→128点）。固定デバイスと、すでに単位へ一致している値は変更しない。
- 「ファイルレジスタへ全領域割当」は、その機種のZR（ZRがなければR）と同じ容量領域にある変更可能な他デバイスを0点にし、固定使用分を差し引いた残りを設定単位内で最大割当する。デバイス固有の最大点数に達して全容量を使えない場合は未割当容量を表示する。
- 各デバイスの現在の使用範囲は入力表と「機種仕様・備考」へ表示する。備考の設定点数と範囲はKで省略せず、例として `7,680点 / M0～M7679` のように実数で表示する。X/Y/B/W等の末尾番号はデバイス定義の進数に従う。
- 「設定結果をExcel用にコピー」はタブ区切り/改行区切りでクリップボードへ出力する。Excelの左上セルへ貼り付けると、型式、オプション、容量判定、デバイス設定、設定単位、使用範囲、プログラム/メモリ/補助デバイス、出典が行列へ分割される。点数と使用範囲はKで省略しない。Excelのマクロ、VBA、COM自動操作は使用しない。
- 補助入力の1列貼り付けは画面の表示順に対応する。2列貼り付けは1列目を記号またはデバイス名、2列目を点数とする。
- 固定デバイスは貼り付け対象の行として消費するが値は変更しない。
- 進数は使用範囲の末尾表示に反映する。iQ-FのX/Yは8進、Q/iQ-R系のX/YやB/W系は16進で表示する。
- デバイスエリア使用率と、共有メモリ割付合計は別々に検査する。
- 実機への書込み機能は持たない。設計時の容量確認用であり、最終値は対象CPUのマニュアルとGX Worksプロジェクト設定で確認する。
