# MELSEC PC Parameter Assistant

最終更新: 2026-07-17

PLC型式ごとのJSON定義を使い、デバイス点数をメモリ容量へ換算するローカルWebアプリです。型式選択、対応SRAMの絞り込み、初期値からの設定、使用率と容量超過の即時判定、設定結果のExcel資料化に対応しています。入力表は `image.xlsx` のGX Works2/GX Works3画面を参照した連続フォームで、Excelマクロ/VBAは使用していません。

基本操作は「PLCシリーズを選ぶ → PLC型式を選ぶ → 初期値入りの表を調整する → 必要なら［設定単位に切り上げ補正］または［ファイルレジスタへ全領域割当］→ 容量判定を確認する → ［設定結果をExcel用にコピー］→ Excelの左上セルへ貼り付け」です。型式・判定・デバイス点数・設定単位・機種仕様がタブ区切りでセルへ展開されます。Excelからアプリへの一括入力は、既存資料を再利用するときだけ使う折りたたみ式の補助機能です。入力中に点数を勝手に補正することはありません。

各デバイスの現在の使用範囲は入力表と「機種仕様・備考」に表示します。備考ではK表記に省略せず、`7,680点 / M0～M7679` のように実際の点数と末尾番号を表示します。

調査内容と計算根拠は [docs/MELSEC-device-rules.md](docs/MELSEC-device-rules.md) を参照してください。

`Manual/` のメーカー資料と `image.xlsx` はローカル調査用資料です。ファイルサイズと再配布条件を考慮し、GitHubリポジトリには含めません。アプリの実行には不要です。

## 画面構成と操作

1. 「PLCシリーズ・型式とメモリ構成」でシリーズを先に選び、絞り込まれた候補からCPU型式を選択します。SRAM／保持オプションは、その型式で許可された製品だけを表示します。SDカードはバックアップ用途のため選択肢には出ません。
2. 「デバイス設定」には機種別JSONの初期値が入ります。青文字の点数セルを直接編集できます。`8K` のような入力も可能ですが、1Kは1,024点として計算します。
3. 「設定単位に切り上げ補正」を押すと、32点単位などの設定単位へ必要点数を下回らない方向で補正します。入力中の自動補正は行いません。
4. 「ファイルレジスタへ全領域割当」を押すと、ZR（ZRがない機種はR）と同じ容量領域にある変更可能な他デバイスを0点にし、固定使用分を除く割当可能な最大点数を設定します。デバイス上限のため使い切れない容量は未割当として表示します。
5. 「容量判定」で領域別の使用量、使用率、残量と容量超過を確認します。
6. 「機種仕様・備考」でプログラム／メモリ仕様、補助デバイス、現在のデバイス使用範囲を確認します。点数と範囲はKで省略せず、`7,680点 / M0～M7679` の形式で表示します。
7. 「設定結果をExcel用にコピー」を押し、Excelの貼り付け先左上セルへ貼り付けます。型式、オプション、容量判定、デバイス設定、使用範囲、機種仕様、出典がタブ区切りでセルに展開されます。

「既存設定をまとめて入力する場合」は任意の補助機能です。Excelを入力元にすることは前提ではなく、過去資料の数値を再利用するときだけ1列または「記号＋数値」の2列を貼り付けます。

## 起動

.NET 10 SDKが必要です。

通常は [MELSEC_PC_Param.bat](MELSEC_PC_Param.bat) をダブルクリックしてください。`http://localhost:5179` でアプリを起動し、既定ブラウザーを自動で開きます。終了するときはBATのコンソール画面で `Ctrl+C` を押します。

コマンドで起動する場合：

```powershell
dotnet run --project .\MelsecParam.App\MelsecParam.App.csproj
```

コンソールに表示された `http://localhost:...` をブラウザーで開きます。

## テスト

```powershell
dotnet test .\MELSEC_PC_Param.slnx
```

参考ExcelのGX Works2/GX Works3計算結果、JSON読込み、初期値、設定単位、PLC型式別のオプション制限、後継品関係、QnUDVの拡張SRAM容量を自動確認します。現在は12件のテストを実装しています。

## 定義の修正

- PLC型式、容量、選択可能オプション: `MelsecParam.App/Definitions/Models/*.json`
- デバイス共通計算ルール: `MelsecParam.App/Definitions/RuleSets/*.json`
- P/I/SM/SD/FX/FY/FDの共通仕様: `MelsecParam.App/Definitions/SystemDeviceProfiles/*.json`
- SRAM/保持用品とバックアップ用品: `MelsecParam.App/Definitions/memory-options.json`

型式で選べる製品は、各機種JSONの `allowedMemoryOptionIds` にIDを列挙します。通常iQ-R用SRAMとプロセスCPU用ECC品のように、共通リストに存在していても機種側で許可されていない製品は表示・計算されません。

SDカードはバックアップ専用の参考定義であり、画面の選択肢にもデバイス容量にも含めません。`allowedStorageOptionIds` は `none` のみ許可されます。

JSON変更後はアプリを再起動し、`dotnet test` を実行してください。不正なID、重複、対応外のSD選択などは起動時の定義検証で検出されます。

## 将来のGitHub Pages公開

現行版はASP.NET Coreの `/api/catalog` を使用するため、そのままGitHub Pagesへコピーしても動作しません。ただし容量計算はブラウザー側で完結しています。将来は機種別JSONから公開用 `catalog.json` を事前生成し、静的なHTML/CSS/JavaScriptから相対URLで読み込む構成にすればGitHub Pagesへ公開できます。機種別JSONを編集元として維持したまま静的版を生成する方針とします。
